Understanding Claude

Core Concepts

Before writing complex applications, understand how Claude thinks and how to communicate with it effectively.

🧠 What is Claude?

Claude is a large language model (LLM) made by Anthropic. Unlike a search engine, Claude reasons about your prompt and generates a contextually appropriate response. For programming, this means you can describe what you want in plain English and Claude will produce working code, explain algorithms, debug errors, and more.

How Claude Processes Text: Tokens

Claude doesn't see characters — it sees tokens. A token ≈ 4 characters or ¾ of a word.

Maintaining Conversation State in C++

Claude has no memory between API calls — you must send the full history each time. Here's how to manage this in C++:

conversation.hpp 
#pragma once
#include <vector>
#include <string>
#include <nlohmann/json.hpp>
using json = nlohmann::json;

class ClaudeConversation {
public:
    explicit ClaudeConversation(std::string systemPrompt)
        : system_(std::move(systemPrompt)) {}

    // Add a user turn and get Claude's response
    std::string chat(const std::string& userMsg) {
        history_.push_back({{"role","user"},{"content",userMsg}});

        json body = {
            {"model", "claude-sonnet-4-20250514"},
            {"max_tokens", 2048},
            {"system", system_},
            {"messages", history_}  // Send full history!
        };

        std::string response = callAPI(body);

        // Append Claude's reply to history
        history_.push_back({{"role","assistant"},{"content",response}});

        return response;
    }

    void reset() { history_.clear(); }

private:
    std::string system_;
    json history_ = json::array();
    std::string callAPI(const json& body); // Implementation in .cpp
};

Vibe Coding Best Practices

  • Start broad, narrow down — don't try to spec everything upfront
  • Paste your errors — Claude reads compiler output and fixes it
  • Ask for explanations — say "explain what this does" after each iteration
  • Guide the vibe — say "make it faster", "cleaner", "more readable"
  • Always review — Claude can produce bugs; run tests and read the code
  • Commit frequently — use git so you can revert bad iterations

Chapter 04

Dynamic Programming Fundamentals

Dynamic Programming (DP) is an algorithm technique for solving optimization problems by breaking them into overlapping subproblems. Claude excels at generating, explaining, and debugging DP code.

🧩 The Two Properties of DP

1. Optimal Substructure: The optimal solution to the problem contains optimal solutions to subproblems.

2. Overlapping Subproblems: The same subproblems are solved multiple times. DP stores results to avoid recomputation.

Problem 1: Fibonacci — From Recursion to DP Beginner

The classic example showing why memoization matters.

fibonacci_naive.cpp — O(2ⁿ) time 
// BAD: Exponential time — fib(50) takes minutes!
long long fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
    // fib(5) recomputes fib(3) twice, fib(2) three times...
}
Problem: fib(40) makes 2.7 billion recursive calls. The same subproblems are recomputed exponentially many times.
fibonacci_memo.cpp — Top-Down DP (Memoization) 
#include <unordered_map>

// Top-Down DP: Recursion + cache (memoization)
long long fib(int n, std::unordered_map<int,long long>& memo) {
    if (n <= 1) return n;

    auto it = memo.find(n);
    if (it != memo.end()) return it->second; // Cache hit!

    // Compute and store in cache
    memo[n] = fib(n - 1, memo) + fib(n - 2, memo);
    return memo[n];
}

long long fibonacci(int n) {
    std::unordered_map<int,long long> memo;
    return fib(n, memo);
}
// Time: O(n), Space: O(n)
fibonacci_tab.cpp — Bottom-Up DP (Tabulation) 
#include <vector>

// Bottom-Up DP: Fill table iteratively, no recursion
long long fibonacci(int n) {
    if (n <= 1) return n;

    std::vector<long long> dp(n + 1);
    dp[0] = 0;
    dp[1] = 1;

    for (int i = 2; i <= n; ++i)
        dp[i] = dp[i - 1] + dp[i - 2];

    return dp[n];
}
// Time: O(n), Space: O(n)
// Better than memoization: no recursion overhead, cache-friendly
fibonacci_optimal.cpp — O(1) Space 
// OPTIMAL: We only need last 2 values
long long fibonacci(int n) {
    if (n <= 1) return n;
    long long prev2 = 0, prev1 = 1;

    for (int i = 2; i <= n; ++i) {
        long long curr = prev1 + prev2;
        prev2 = prev1;
        prev1 = curr;
    }
    return prev1;
}
// Time: O(n), Space: O(1) ← Best possible!
💡 Space Optimization Pattern: Many DP problems only look back a fixed number of rows/columns. Recognize this and you can often reduce O(n²) space to O(n) or O(1).

Problem 2: 0/1 Knapsack Intermediate

Given items with weights and values, maximize value within a weight limit. Each item can be taken or left — hence 0/1.

DP Table Visualization — Items: {(w=2,v=6), (w=3,v=10), (w=4,v=12)}, Capacity=5

Item ↓ / Cap → 012345
No items 000000
(w=2,v=6) 006666
(w=3,v=10) 006101016
(w=4,v=12) 006101216

★ Answer: 16 (take items 1 and 2). Yellow = maximum value at this capacity.

knapsack.cpp — Claude-generated with explanation 
#include <vector>
#include <algorithm>
#include <cassert>
using namespace std;

struct Item {
    int weight;
    int value;
};

// Returns maximum value achievable with given capacity
// Time: O(n * capacity), Space: O(n * capacity)
int knapsack(const vector<Item>& items, int capacity) {
    assert(capacity >= 0);
    int n = (int)items.size();

    // dp[i][w] = max value using first i items with weight limit w
    vector<vector<int>> dp(n + 1, vector<int>(capacity + 1, 0));

    for (int i = 1; i <= n; ++i) {
        for (int w = 0; w <= capacity; ++w) {
            // Option 1: Don't take item i
            dp[i][w] = dp[i - 1][w];

            // Option 2: Take item i (if it fits)
            if (items[i - 1].weight <= w) {
                int valueWithItem = items[i-1].value
                    + dp[i-1][w - items[i-1].weight];
                dp[i][w] = max(dp[i][w], valueWithItem);
            }
        }
    }
    return dp[n][capacity];
}

// Space-optimized version: O(capacity) space
int knapsackOptimized(const vector<Item>& items, int capacity) {
    vector<int> dp(capacity + 1, 0);

    for (const auto& item : items)
        for (int w = capacity; w >= item.weight; --w)
            dp[w] = max(dp[w], item.value + dp[w - item.weight]);
            // Iterate right-to-left to avoid using item twice!

    return dp[capacity];
}

Problem 3: Longest Common Subsequence (LCS) Intermediate Claude-Guided

Find the longest subsequence present in both strings. Classic example of 2D DP. Used in diff tools and bioinformatics.

LCS Table — "ABCBDAB" vs "BDCAB"

BDCAB
000000
A000011
B011112
C011222
B011223
D012223
A012233
B012234

LCS length = 4 (e.g., "BCAB" or "BDAB")

lcs.cpp — with backtracking to reconstruct the sequence 
#include <string>
#include <vector>
#include <algorithm>

struct LCSResult {
    int length;
    std::string sequence;
};

LCSResult longestCommonSubsequence(
    const std::string& s1, const std::string& s2)
{
    int m = s1.size(), n = s2.size();

    // Build DP table
    std::vector<std::vector<int>> dp(m + 1,
        std::vector<int>(n + 1, 0));

    for (int i = 1; i <= m; ++i) {
        for (int j = 1; j <= n; ++j) {
            if (s1[i-1] == s2[j-1])         // Match!
                dp[i][j] = dp[i-1][j-1] + 1;
            else                                  // No match
                dp[i][j] = std::max(dp[i-1][j], dp[i][j-1]);
        }
    }

    // Backtrack to find the actual sequence
    std::string lcs;
    int i = m, j = n;
    while (i > 0 && j > 0) {
        if (s1[i-1] == s2[j-1]) {
            lcs += s1[i-1];
            --i; --j;
        } else if (dp[i-1][j] > dp[i][j-1]) --i;
        else --j;
    }
    std::reverse(lcs.begin(), lcs.end());

    return {dp[m][n], lcs};
}

// Usage:
// auto [len, seq] = longestCommonSubsequence("ABCBDAB", "BDCAB");
// len == 4, seq == "BCAB" (or "BDAB")

Problem 4: Edit Distance (Levenshtein) Intermediate

How many insertions, deletions, or substitutions to transform one string into another? Powers spell-checkers and DNA sequencing.

edit_distance.cpp 
int editDistance(const std::string& s, const std::string& t) {
    int m = s.size(), n = t.size();

    // Space-optimized: only keep 2 rows at a time
    std::vector<int> prev(n + 1), curr(n + 1);

    // Base case: transform empty string to t[0..j]
    for (int j = 0; j <= n; ++j) prev[j] = j;

    for (int i = 1; i <= m; ++i) {
        curr[0] = i; // Transform s[0..i] to empty string
        for (int j = 1; j <= n; ++j) {
            if (s[i-1] == t[j-1])
                curr[j] = prev[j-1];   // No operation needed
            else
                curr[j] = 1 + std::min({
                    prev[j],    // Delete
                    curr[j-1], // Insert
                    prev[j-1]  // Replace
                });
        }
        std::swap(prev, curr);
    }
    return prev[n];
}
// editDistance("kitten", "sitting") == 3

int coinChange(std::vector<int> coins, int amount) {
    std::vector<int> dp(amount + 1, amount + 1); // Infinity
    dp[0] = 0;

    for (int i = 1; i <= amount; ++i)
        for (int coin : coins)
            if (coin <= i)
                dp[i] = std::min(dp[i], dp[i - coin] + 1);

    return dp[amount] > amount ? -1 : dp[amount];
}

/* Claude adds backtracking: */
struct CoinResult { int minCoins; std::vector<int> coinsUsed; };

CoinResult coinChangeTracked(std::vector<int> coins, int amount) {
    std::vector<int> dp(amount + 1, amount + 1);
    std::vector<int> parent(amount + 1, -1); // Track chosen coin
    dp[0] = 0;

    for (int i = 1; i <= amount; ++i)
        for (int coin : coins)
            if (coin <= i && dp[i - coin] + 1 < dp[i]) {
                dp[i] = dp[i - coin] + 1;
                parent[i] = coin; // Remember this choice
            }

    if (dp[amount] > amount) return {-1, {}};

    // Reconstruct path
    std::vector<int> used;
    for (int rem = amount; rem > 0; rem -= parent[rem])
        used.push_back(parent[rem]);

    return {dp[amount], used};
}

            });
        }

        messages.push_back({{"role","user"},{"content",toolResults}});
    }
}
💡 Agent Loop Pattern: Keep looping until stop_reason == "end_turn". Every time Claude calls a tool, execute it and send back a tool_result message. Claude may call multiple tools before giving its final answer.

int main(int argc, char** argv) {
    if (argc < 3) {
        std::cerr << "Usage: packer <items.csv> <max_weight>\n";
        return 1;

    auto items = readItemsCSV(argv[1]);
    int capacity = std::stoi(argv[2]);

    printHeader("Smart Packer — Powered by Claude + DP");
    printItems(items);

    // 2. Run knapsack DP
    auto result = knapsackWithTracking(items, capacity);

    printPackingResult(result);
    printDPTable(items, capacity);

    // 3. Ask Claude to explain the result
    ClaudeClient claude("You are a helpful packing optimizer assistant.");

    std::string prompt = buildExplanationPrompt(items, result, capacity);
    std::string explanation = claude.chat(prompt);

    printSection("Claude's Analysis");
    std::cout << explanation << "\n";

    // 4. Interactive mode: ask Claude questions
    std::cout << "\nAsk Claude anything about this packing decision:\n";
    std::string userQ;
    while (std::getline(std::cin, userQ) && userQ != "quit") {
        std::cout << "\nClaude: " << claude.chat(userQ) << "\n\n> ";
    }

    return 0;

Visual Studio Tips for Claude Development

🔍

GitHub Copilot + Claude

Use VS GitHub Copilot for inline autocomplete (fast) and Claude API for larger reasoning tasks (deep). They complement each other perfectly.

🐛

Paste Errors to Claude

When you get a red squiggle or crash, copy the full error including the call stack from VS Output window and paste it to Claude. It fixes 90% of errors instantly.

⚙️

natvis for DP Tables

Create a .natvis file in VS to visualize 2D vectors in the debugger as a table — perfect for inspecting DP arrays while debugging.

Final Vibe Coding Manifesto

  • Your job is intent, not implementation — describe what you want clearly
  • Iteration beats perfection — get something working, then refine
  • Understand what Claude gives you — you own the code, not Claude
  • Use Claude to learn — ask "why" after every answer
  • Build your prompt library — save prompts that work well
  • Test everything — Claude can produce plausible but wrong code
