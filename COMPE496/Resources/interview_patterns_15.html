Pattern Recognition Cheat Sheet

A mental decision tree for spotting the right technique from problem language alone.

Hash map

Need fast lookup of seen values, frequencies, complements, or indices.

Two pointers

Sorted data, pair/triple search, in-place dedupe, partitioning, or window boundaries.

Sliding window

Contiguous subarray/substring with a running constraint.

Sort + intervals

Need to merge, detect overlap, or schedule resources.

Stack / monotonic stack

Matching, rollback, nearest greater/smaller, histogram geometry.

Binary search

Monotonic answer space or sorted structure.

BFS / DFS

Connectivity, layers, reachability, or recursive tree/graph structure.

Heap

Repeated access to min/max among a changing candidate set.

Backtracking

Enumerate valid choices with pruning.

Dynamic programming

Optimal answer built from overlapping subproblems.

Cross-Problem Tactics to Teach Explicitly

  • Always start with the brute force baseline. It demonstrates understanding and creates a contrast with the optimized method.
  • Name the invariant. e.g., "the window is valid", "the stack is monotonic decreasing", "dp[i] means the best answer ending at i".
  • Justify the data structure. Queue for layers, stack for reversal/nearest greater, heap for rolling min/max among active candidates.
  • State how duplicates are handled. Crucial in 3Sum, intervals, subsets/combinations, and hash-map grouping.
  • Define the recursive return value contract before writing code (especially LCA, tree DP).
  • Group cases into phases rather than branching on every micro-scenario (Insert Interval).
